## 产品实现

产品定位为运行在单台 Windows 笔记本上的无登录、单用户、单实例专业规划工具。主界面以 Mars3D 三维地图为核心，任务库、任务参数和计算状态作为辅助工作区，不建设账号、组织、审批或多租户功能。

### 主要工作流

1. 启动工具并完成 WebGL、本地服务、Mars3D 资源和地理数据包自检。
2. 从任务库新建或打开任务，录入任务点及天线高度。
3. 选择遮挡模式、阈值、有效地球半径系数和覆盖图接收端高度。
4. 使用默认道路范围或 Mars3D 手绘区域设置升空限制区域。
5. 预估候选点规模；通过校验后开始全量计算，支持取消和续算。
6. 在 Mars3D 地图中筛选候选点，查看双档最低高度和覆盖任务点。
7. 选择候选点，加载 30km 红绿覆盖栅格与 GeoJSON 边界、统计信息。
8. 保存、复制、导入导出任务，或显式开启局域网只读接口供无人机控制系统读取。

### 关键状态

- 加载：地图骨架与本地数据自检并行展示，不使用全屏无限等待。
- 空任务：地图保持可操作，任务面板引导创建首个任务点。
- 校验错误：定位到具体任务点、参数、数据图层或区域，不启动计算。
- 计算中：显示阶段、完成批次、候选点数量、预计剩余时间和取消入口。
- 已暂停：显示检查点时间、签名和继续/从头计算操作。
- 已失效：保留旧结果但明显标记不可用，禁止接口与导出按有效结果读取。
- 失败：保留最后完整任务状态和可诊断错误，不返回伪结果。
- 只读归档：可查看包内结果和数据版本，禁止编辑与重新计算。

## 系统架构

### 部署结构

```text
Windows 离线笔记本
├── Electron 桌面壳
│   ├── 单实例与窗口生命周期
│   └── 安全的 Chromium 运行时
├── Vue + TypeScript 应用
│   └── Mars3D 唯一地图引擎
├── 本地应用服务（127.0.0.1 动态端口）
│   ├── REST API 与静态资源
│   ├── 任务库与任务包
│   ├── 地理数据包与本地瓦片服务
│   └── 计算任务与检查点调度
└── 本地数值分析工作进程
    ├── 坐标、栅格和矢量处理
    ├── 批量视距与覆盖计算
    └── 结果栅格、GeoJSON 与统计生成
```

### 边界与依赖方向

- Mars3D 是唯一地图引擎。所有底图、地形、标绘、候选点、红绿覆盖和交互均由 Mars3D 图层与对象呈现。
- 数值分析工作进程不渲染地图，只接收版本化任务快照和数据包引用，返回版本化结果文件及统计。
- Vue 应用只能通过本地 REST API 读写任务，不直接访问 SQLite 或计算进程文件。
- 计算进程只能通过任务调度器取得不可变输入快照，不能直接修改任务当前版本。
- Electron 主进程只管理窗口、进程、安装资源和系统能力，不承载业务规则。
- 互联网天地图仅是开发数据提供方；工程配置没有公网回退路径。

### 模块职责

- `desktop-shell`：单实例、进程启动/关闭、故障恢复、安装与更新边界。
- `map-workbench`：Mars3D 初始化、图层、绘制、筛选、候选详情、覆盖展示。
- `task-service`：任务状态机、自动保存、历史版本、回收站、复制、导入导出。
- `data-package-service`：数据清单、校验和、坐标系、覆盖范围、版本和本地服务地址。
- `candidate-service`：可行域、道路采样、固定网格、去重和 50,000 点上限。
- `analysis-service`：任务点最低可视高度计算、覆盖聚合、连续覆盖范围与参数追踪。
- `job-service`：进度、取消、检查点、续算、错误和结果原子发布。
- `external-api`：本机/局域网只读接口、令牌、白名单、条件请求和调用日志。

## 数据设计

### 核心实体

- `Task`：任务标识、名称、状态、当前修订、当前有效计算、创建/更新时间、删除时间。
- `TaskPoint`：任务点标识、名称、经纬度、工作坐标、裸地高程、天线离地高度。
- `LaunchConstraint`：道路或手绘来源、原始几何、规范化几何、数据版本。
- `AnalysisConfig`：遮挡模式、部分覆盖阈值、`k`、高度档位、最大距离、覆盖图接收端高度。
- `DataPackage`：包标识、版本、范围、CRS、分辨率、DTM/DSM/道路/瓦片清单及 SHA-256。
- `TaskRevision`：最近 10 个输入与参数快照，不包含大型结果。
- `CalculationRun`：计算签名、引擎版本、状态、进度、开始/结束时间、错误。
- `Checkpoint`：运行标识、批次边界、已完成工作、校验和和版本。
- `Candidate`：地面坐标、最高档位、双档最低高度、覆盖数量与任务点集合。
- `CoverageArtifact`：候选标识、接收端高度、结果瓦片、GeoJSON 边界、统计、校验和。
- `ApiSetting`：局域网开关、令牌摘要、可选白名单和更新时间。
- `ApiLog`：时间、来源、接口、状态、任务和结果版本，不保存令牌。

### 状态模型

`Task` 状态：`draft`、`ready`、`computing`、`paused`、`completed`、`stale`、`failed`、`archived_readonly`、`deleted`。

`CalculationRun` 状态：`queued`、`running`、`canceling`、`paused`、`completed`、`failed`、`discarded`。

有效结果必须同时满足：运行状态为 `completed`、计算签名与当前任务一致、结果清单校验通过、数据包版本可用。任何条件不满足都不能通过接口或部署导出作为当前结果使用。

### 本地存储

- 任务元数据使用 SQLite，单实例下启用 WAL、外键和事务。
- 大型栅格、瓦片、GeoJSON、任务包和检查点使用内容寻址文件目录，数据库只保存清单与校验和。
- 自动保存使用事务与临时文件原子替换，失败时保留最后完整版本。
- 地理数据包独立于任务库安装；任务仅保存包标识、版本和校验和。
- 回收站通过删除时间管理，30 天清理任务及其未被其他任务引用的文件。
- 数据结构与任务包具有显式 schema 版本和向前迁移程序；迁移前自动备份元数据。

### 地理数据契约

- 开发底图：天地图 WMTS，仅开发配置和本机 Key。
- 工程底图：本地 XYZ。
- 地形显示：Cesium Quantized Mesh。
- 数值计算：项目方提供的 DTM 和 DSM 原始高程栅格，导入后统一到经验证的湖北工作投影。
- 路网：项目方矢量路网，导入后生成分析中心线与 Mars3D 矢量瓦片。
- 覆盖结果：本地彩色栅格瓦片、GeoJSON 边界与 JSON 统计。
- 数据包导入必须校验范围、CRS、像元、NoData、垂直单位、DTM/DSM 对齐、道路拓扑、许可说明和完整性。

## 接口与集成

### 本地内部接口

- Electron 启动本地服务后，通过一次性启动密钥完成渲染进程握手。
- 前端 API 使用 `/api/v1`，任务修改采用版本号或 `If-Match` 防止旧页面覆盖新状态。
- 计算任务提交不可变输入快照，返回作业 ID；进度使用本机事件流，外部接口仍采用轮询。
- 结果发布采用“两阶段”方式：先写文件与清单并校验，再在单个事务中切换当前有效结果。

### 外部只读接口

- `GET /api/v1/tasks`：可读取的有效任务列表。
- `GET /api/v1/tasks/{id}`：任务、参数、数据版本和状态快照。
- `GET /api/v1/tasks/{id}/points`：任务点 JSON/GeoJSON。
- `GET /api/v1/tasks/{id}/candidates`：分页候选点和筛选参数。
- `GET /api/v1/tasks/{id}/candidates/{candidateId}/coverage`：覆盖元数据、GeoJSON 与瓦片模板。
- `GET /api/v1/map/manifest`：本地底图、地形和路网服务清单。
- 快照返回结果版本、`ETag` 和数据包版本；支持条件请求。
- 错误使用稳定错误码区分无权限、不存在、计算中、结果失效、数据不匹配和内部失败。

### 幂等与恢复

- 所有 GET 接口无副作用。
- 任务包导入先在隔离目录校验，成功后一次性加入任务库；失败不留半成品。
- 计算取消只改变作业状态并封存完整检查点，不发布部分结果。
- 重启后扫描运行中作业：签名一致且检查点完整则可继续，否则标记为需从头计算。

## 权限与安全

- 工具界面无登录、无用户和角色；本机文件权限承担本地访问边界。
- Electron 开启 `contextIsolation`、渲染进程沙箱和严格 CSP，关闭 `nodeIntegration`，仅通过最小 preload API 访问系统能力。
- 本地服务默认只绑定 `127.0.0.1`，端口动态选择，启动密钥不写日志。
- 局域网模式必须显式开启并配置固定高强度令牌；IP/CIDR 白名单可选，关闭局域网或修改令牌立即失效。
- 令牌使用操作系统安全存储或不可逆摘要保存，不进入任务包、日志、错误信息或界面截图。
- 天地图 Key 只存在开发机本地配置，版本库提供无密钥示例文件。
- 外部 API 只读，限制请求频率、分页大小、GeoJSON范围和瓦片路径，防止资源耗尽与路径穿越。
- 导入文件进行大小、格式、路径、压缩炸弹和校验和检查。
- 调用日志按 90 天或 100MB 先到者滚动清理；敏感坐标不写普通运行日志正文。

### 批量视距算法

1. 将 DTM/DSM 和道路转换到工作投影与统一分辨率，保留原始数据校验和。
2. 生成两个覆盖档位的距离可行域，再与道路或手绘限制区域相交。
3. 生成并去重最多 50,000 个地面候选点。
4. 对每个任务点使用成熟 viewshed 算法生成“各栅格位置达到可视所需的最低目标高度”。
5. 裸地模式直接使用 DTM；地表模式使用 DSM 判断路径遮挡，并用 DTM/DSM 高差校正端点离地高度，避免重复叠加建筑和植被。
6. 将最低目标高度栅格抽样到候选点，按 0、50、100、150、200、250m 聚合覆盖任务点集合。
7. 计算严格超过任务阈值的最低高度和 100% 最低高度，原子发布候选结果。
8. 选择候选点后，以其推荐高度、任务接收端高度、相同遮挡模式和 `k` 生成 30km 连续覆盖结果，再由 Mars3D 加载结果瓦片与 GeoJSON。

有效地球半径系数 `k` 映射到 GDAL 曲率系数 `cc=1/k`；默认 `k=4/3` 对应 `cc=0.75`。合成平地样例已验证该映射的变化方向和结果量级；实施期继续以独立逐射线参考实现做逐像元回归，防止版本升级改变语义。

## 验证策略

### 单元与性质测试

- 任务状态机、参数范围、阈值取整、结果失效、历史版本和回收站时钟。
- 固定网格、道路 25m 采样、交叉点去重、圆域分档裁剪和 50,000 边界。
- 坐标转换往返误差、DTM/DSM端点校正、`k` 到曲率系数映射。
- 任务包 manifest、路径安全、校验和、版本迁移和原子导入。
- 计算签名、检查点损坏、取消、续算和从头计算结果一致性。

### 集成测试

- Mars3D 与本地 XYZ、Quantized Mesh、矢量瓦片、覆盖瓦片和 GeoJSON 联调。
- 天地图开发配置与离线配置切换，工程配置网络请求为零。
- 本地任务库、文件仓储、计算工作进程和 API 的故障注入。
- 局域网令牌、白名单、条件请求、分页、限流和日志滚动。
- 安装、升级、卸载保留数据、异常退出和单实例恢复。

### 算法基准

- 平地、单山脊、凹地、多山脊、NoData边界、地球曲率和折射解析样例。
- DTM 与 DSM 中建筑/植被障碍对照样例。
- 与 GDAL 官方 viewshed、独立逐射线参考实现和人工几何结果三方比对。
- 1、10、50 个任务点以及 49,999、50,000、50,001 候选点边界。
- 不同栅格分辨率下的准确度、内存、时间和结果稳定性。

### 端到端与人工验收

- 从新建任务到候选计算、覆盖查看、保存、重启恢复、导出和接口读取完整流程。
- Chrome/Electron WebGL 像素检查，确认 Mars3D 画布非空、红绿覆盖正确且无界面遮挡。
- 断网验收确认无 Mars3D CDN、天地图或其他公网请求。
- 键盘、焦点、触控目标、错误、空状态、禁用状态和减弱动效检查。

### 性能

- 在最终验收硬件和数据包上验证 50 个任务点、50,000 候选点、双模式与 30km 距离的 5 分钟目标。
- 候选点覆盖结果选择到完整红绿覆盖渲染不超过 1 秒。
- 性能测试记录硬件、数据版本、分辨率、冷/热缓存、峰值内存、GPU和每阶段耗时。
- 硬件未锁定前只报告测量值，不声明性能通过。

## 风险与验证结论

| 风险 | 当前证据 | 证伪条件 | 处理 |
| --- | --- | --- | --- |
| Mars3D 被误解为只负责展示 | 官方提供 Sightline、ViewShed、XYZ、WMTS、Terrain 等 API | Mars3D 无法加载本地结果或交互状态不稳定 | Mars3D 保持唯一地图引擎；以官方示例和 API 做集成 POC |
| Mars3D 单独承担批量搜索性能不足 | Sightline 为点对点，ViewShed 为视锥阴影展示，不是 50×50,000 批量最低高度算法 | Mars3D 官方接口实测可在目标规模内生成确定性数值结果 | 后台成熟数值引擎批量计算，Mars3D 加载标准结果；不替换地图引擎 |
| GDAL 曲率与高度语义映射错误 | GDAL 3.13.1 合成 POC：平地/山脊最低高度分别为 0m/202m；200m 不可见而 250m 可见；30km 末端 `cc=0.75`/`1.0` 分别为 34.31m/48.76m | 实施期独立逐射线逐像元回归不一致 | 固化合成样例为算法回归测试；不一致则暂停结果发布并修正模型或替换后台算法 |
| DSM 端点高度重复叠加 | 已定义 DTM 端点基准与 DSM 路径遮挡分工 | 建筑/植被样例与人工几何不一致 | 建立 DTM/DSM 对齐校验和端点高差校正测试 |
| 5 分钟与 1 秒目标不可达 | 任务规模已封顶，但硬件与真实数据未到位 | 参考硬件 POC 超时或内存超限 | 数据分块、并行任务点 viewshed、结果缓存；仍失败则重新打开需求与方案基线，不静默降精度 |
| Windows 离线打包复杂 | Electron 可固定 Chromium；GIS运行时尚未实测封装 | 干净离线 Windows 机器无法安装或启动 | 构建自包含安装包并在虚拟机/物理机做冷安装验收 |
| 真实数据格式与许可未知 | 用户确认后续由项目方提供 | 数据无法转换、精度不足或许可不允许离线加工 | 数据契约与验收工具先行；不合格数据不得进入正式包 |

### 已完成核验

- Mars3D 官方文档确认离线静态资源、WebGL 环境、本地 XYZ/WMTS/Terrain 图层及 Sightline/ViewShed 能力。
- 当前 npm 元数据确认 `mars3d@3.11.5`、`mars3d-cesium@1.143.0` 为候选稳定版本，许可证为 Apache-2.0。
- 天地图官方文档确认 WMTS 服务需要 Key，开发 Key 必须外置。
- GDAL 官方文档确认 viewshed 只应在投影坐标系使用，并支持观察高度、目标高度、最大距离、曲率折射和最低可视高度输出。
- Windows 临时自包含 GDAL 3.13.1 运行时已完成合成数据 POC，并显式隔离 `PROJ_LIB` 与 `GDAL_DATA`，避免系统 PostgreSQL 的 `proj.db` 干扰。
- 2km、10m 像元平地样例中，观察点离地 2m、目标点距观察点 1km 时，`GROUND` 最低目标高度为 `0m`。
- 同样例加入横跨视线的 100m 山脊后，目标点最低离地高度为 `202m`；`NORMAL` 模式复核为 200m 不可见、250m 可见，符合项目 50m 高度档位判定。
- 30km、10m 像元平地样例中，末端最低目标高度在 `cc=0.75` 时为 `34.311955m`，在 `cc=1.0` 时为 `48.756712m`；折射后所需高度降低，与有效地球半径解析几何一致。
- 平地与山脊对照证明 DTM 裸地路径和 DSM 障碍路径可使用同一成熟 viewshed 内核，端点 DTM/DSM 高差校正仍需在实施期以建筑样例固化回归。

### 后续实施验证与已知限制

- Mars3D 是强制且唯一的地图引擎；本地 XYZ、Quantized Mesh、矢量瓦片、覆盖瓦片和 GeoJSON 的组合加载在外部原型核验后进入首个集成切片验证。
- 独立逐射线参考实现、建筑端点高差、NoData 和多山脊样例将在算法切片中转为自动回归测试。
- 真实湖北数据与验收硬件尚未到位，无法完成 50 个任务点、50,000 候选点的 5 分钟目标和覆盖显示 1 秒目标实测；交付验收必须记录硬件、数据版本、分辨率、缓存状态和分阶段耗时。
- 若真实数据或参考硬件使目标不可达，不允许静默降低分辨率或精度；先进行分块、并行和缓存优化，仍失败则重新打开需求与方案基线。
